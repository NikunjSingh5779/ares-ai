## 1. Non-Negotiable Standing Rules

Apply on every iteration, no exceptions:

1. **Never change a safety/risk numeric constant** — consensus threshold, kill-switch max drawdown, position size limits, or similar — without an explicit, separate instruction naming the exact new value. If a backlog item seems to need it, stop and ask.
2. **No silent failure paths.** Any `except`/`catch` that can swallow an error must log it, with enough context to tell apart "call failed," "response was unparseable," and "unexpected exception."
3. **Every fallback must be recorded, not just logged.** If a function substitutes a deterministic/rule-based result for a real one, that fact must be queryable downstream (a log field, a metric, a status flag) — not just a line that scrolls off a log file. 4. **One backlog item per iteration.** Don't fold unrelated fixes into one commit.
5. **Tests are part of the fix, not optional.** A change without a test that would have caught the original bug isn't done.
6. **Docs are part of the fix.** If a change touches anything described in `README.md`, `AGENTS.md`, `CLAUDE.md`, or `docs/milestone-roadmap.md`, update those files in the *same* commit. Doc drift gets treated as a bug, same severity class as a code bug.
7. **Re-verify before editing.** Never trust this file's description of "current state" over the actual file on disk.
8. **Never invent a model ID, exchange API behavior, or library version.** Confirm a fallback entry actually resolves before adding it — this repo already has entries marked `[UNVERIFIED]`; don't add more.
9. **Anything touching live execution or safety gates** (`live_trading/`, `safety.py`) gets flagged for explicit human confirmation before implementation, even mid-loop.
10. Work on a feature branch, not directly on main (adjust if your actual convention differs) — `fix/<short-slug>` or `feat/<short-slug>`.

## 5. The Loop

Repeat every turn.

**Step 0 — Orient** *(every iteration, no exceptions)*
- `git log -5 --oneline`; skim the last commit's diff to see what changed since the previous iteration.
- Re-read `AGENTS.md` and `CLAUDE.md` in full — not from memory.
- Re-check the top open backlog item against the actual file/line it references. If already resolved, mark it done in your report and move to the next one in the same turn.

**Step 1 — Select**
- Take the single highest-priority open item from Section 4. If the backlog is empty, run Step 1a first.

**Step 1a — Discovery pass** *(only once the seeded backlog is exhausted)*
- Re-run the full test suite; capture new failures.
- Grep `agents/` for bare `except`/`except Exception` blocks with no logging call inside — Item 1's pattern may recur elsewhere.
- Re-run `agent-spec-sync`'s roster-diff between the docs and `configs/models.yaml`.
- Add findings to the backlog, prioritized: correctness/safety > reliability > drift/cosmetic.

**Step 2 — Load the skill**
- Identify the 1–3 relevant skills from Section 2 and read their full `SKILL.md` before writing any code.

**Step 3 — Implement**
- Branch `fix/<short-slug>`. Smallest change that fully resolves the item — no drive-by refactors.
- Standing Rules in Section 1 apply throughout, especially Rule 1 (no threshold changes) and Rule 9 (flag anything touching live execution).

**Step 4 — Prove it**
- Add or update a test that would have caught the original issue. Run the *full* suite, not just the new test.
- For anything touching LLM parsing or agent output: run or replay one cycle and confirm the log record now correctly distinguishes real vs. fallback output.

**Step 5 — Sync docs**
- Update any of `README.md` / `AGENTS.md` / `CLAUDE.md` / `docs/milestone-roadmap.md` this change touches, in the same commit.

**Step 6 — Commit**
- One logical change. Message format: `fix(scope): what changed — why — verified by <test>`.
